# 实机测试通知约定（运维说明）

适用范围：本人需要安装测试包，或进入游戏完成实机验收时。此通知是执行提醒，不是产品决策卡；不加选择按钮，也不以发送或已读表示验收通过。

其他工作继续按《星图中台发卡规矩》处理：只有识别逻辑、发布、推翻既定决定发 `ask`；一般索取资料、恢复登录或请本人提供帮助仍进每日汇总；中台自定事项记入汇总。通知不得绕过发布门槛。

## 通知正文模板

标题：请安装测试包并验收「安装与更新」

正文（按本次任务填充）：

- 测试内容：<要验证的安装行为或实机功能>
- 测试包：<本人可访问的真实安装包位置；没有位置时先不要发送>
- 隔离安装目录：<独立于现用安装的位置；不得覆盖现用安装>
- 打开方式：在隔离目录安装后，从开始菜单或桌面快捷方式打开星图。
- 验收步骤：1. <操作>；2. <操作>；3. <操作>；4. <可选操作>。
- 异常反馈：回复本通知并附上现象、发生步骤和星图显示的提示；不要上传账号口令。

每次只保留适用的 2 至 4 步。安装前确认测试包身份和隔离目录；禁止覆盖当前在用的安装。若任务只需游戏内验收，删除安装步骤并说明如何启动当前待验版本。未实际完成的项目标为“待验收”；通知送达或已读都不算通过。

## Windows 副本同步清单

规则部署后，再由获授权的同步入口更新本人 Windows 副本：

1. `xingtu-card-policy.md`
2. `feishu-card-style.md`
3. `agent-autoloop` Skill（正文的发卡、浏览器和恢复约定）
4. `review-xingtu-pr` Skill（审查和实机验收通知约定）
5. 所有实际引用以上内容的星图规则提示词，包括 PR 审查、检查失败复查、拆任务、Pip 来源任务、服务器 Codex 任务、打包和发布任务。

同步前后记录版本标识或 SHA-256，对照确认同一补丁已应用；检查规则提示词的所有星图任务变体，不以只更新一个模板为完成。不要复制服务器专属路径、私人令牌或中台连接配置到 Windows 文档。

## 部署与生效核验

应用补丁前备份当前版本，只合入本补丁涉及的段落。先用本机安装的 `agent-autoloop check <草稿>` 检查规则文件；确认合法后才由有权限的运维入口应用。随后再次检查实际运行规则和同步后的 Windows 副本，并验证以下场景：

- 安装测试包时生成实机测试通知。
- 进游戏实机验收时生成实机测试通知。
- 一般索取文件、信息或恢复登录仍只进入每日汇总。
- 识别逻辑、发布、推翻既定决定三类 `ask` 规则和发布按钮保持不变。
- 已完成的 PR #182 本次不补发通知。
- 同一测试包及同一验收事项重复触发时去重，不重复打扰本人。

只做静态检查或隔离预演，不向真实飞书通道发送测试消息、不运行或暂停中台规则。最终记录分别写清“已准备”“已部署”“已同步”“已核实”；没有核对运行规则和 Windows 副本时，不得声称已生效。

## 最小规则片段

由对应任务提示词在本人需要实际测试时提交专用通知事件；消息使用 `notice`，无产品选项，无 `ask`。一般资料请求和账号恢复仍走汇总记录。

```text
本人需要安装测试包或进游戏实机验收：提交一次专用实机测试通知，写明测试内容、真实测试包位置、隔离安装目录、打开方式、2–4 步操作和异常反馈方式。不得覆盖现用安装。发送或已读不等于验收完成；未做项目明确标记待验收。以测试包身份及验收事项去重。此例外不改变发卡规矩里的三类决策 ask、其他事项的每日汇总规则、发布按钮和发布门槛；不补发 PR #182 的通知。
```
