# 星图交付审查要点

这份文件给中台交付流水线（agent-autoloop 的 `delivery`）用：PR 打上 `deliver` 标签后，合并前的自动审查只读本文件 `## 审查要点` 一节和这个 PR 自己的改动。规则以 [AGENTS.md](../AGENTS.md) 和 [开发与交付流程](../docs/development.md) 为准，这里只摘合并前必须拦下的部分。

功能模块的正式名称见中台的星图功能模块清单（14 个模块：地图识别、楼层判断、路线贴合、游戏画面采集、本局与快捷键、手动选图、路线显示、地图资源、自定义图库、路线广场、开箱连点、设置与主界面、排查与帮助、安装与更新；「作者路线」「图包管理」是「地图资源」的别名）。

## 审查要点

只报会让结果出错、丢用户数据、越权或造成发布事故的问题，不挑风格。每条写清文件和行号、什么情况下触发、后果是什么，并尽量用上面的正式模块名说明影响到哪个功能。

1. 识别逻辑须本人确认：改动只要改变了地图识别、楼层判断、路线贴合的判断结果，就报一条——包括识别、匹配、判定、观测、相似度/相似组、阈值、候选范围、楼层或位姿判断、显示授权规则，涉及的文件如 `app/map_identity_engine.py`、`app/runtime_map_recognition.py`、`app/native_similarity_groups.py`、`app/front_door*`、`app/side_door*`、`app/side_entry_*`、`app/nightmare_*`、`app/difficult_*_identity.py`、`app/floor_*`、`app/s0_vertical_controls.py`、`app/s0_floor_templates.py`、`app/s1_floor_observation.py`、`app/front_floor_structure.py`、`app/fast_structure_alignment.py`、`app/alignment_*`、`app/b1_relocalization.py`、`app/structure_cache_memory.py`、`app/s1_pose_prior.py`。标题写「改动识别逻辑，须 huan 本人确认后手动合并」，不要因为看起来正确就放过。纯测试、纯日志或纯文档改动不算。
2. 不要自动发版：改了 `version.json`、安装包脚本或配置（`tools/qt-*.iss`、`tools/qt-*.spec`、安装/更新相关代码）、发布或更新地址的，报一条「涉及发版或安装，须 huan 本机验收」。软件交付只用 Setup，构建、安装、实机验收和发布是不同状态。
3. 两模式共用核心：噩梦与困难共用识别、贴合、楼层切换、正门/侧门策略、任务排队/取消和结果提交。复制出第二套算法、只改一个模式而另一个模式的真实调用会走坏、或用假数据/放宽验证凑一致的，要报。资源缺门、缺绑定应明确返回能力缺口。
4. 相似组只能来自项目明确复核登记的成员表；用局部特征、动态候选或示例数据扩大手选列表或生产成员的，要报。识别用结构证据，作者图和自定义路线只用于显示；换作者不能改变身份、结构位姿或楼层。
5. 迟到结果与线程：后台任务结果必须核对当前请求、帧/页面代际、模式、地图、楼层和资源身份中实际相关的字段；关闭、换层、换图、结束本局后旧结果不能重新显示或确认；UI 更新要在 UI 线程。违反的要报。
6. 用户数据：不能删除或覆盖用户资料、导入的作者包、自定义图库、设置和诊断记录（除已约定的、只清理归属文件的保留期清理）；迁移要先复制、校验再切换，不删旧原件。
7. 不能提交秘密、私人日志、用户配置、原始游戏数据或未授权素材；不能在代码里写死令牌或个人路径。
8. 检查不能被削弱：改 `.github/workflows/` 时，删掉测试组、加 `continue-on-error`、跳过失败、放宽超时去掩盖失败的，要报。只增加触发类型或测试项不算问题。
9. 缓存要绑定实际资源和显示来源；更新资源后要清理对应缓存与旧任务。只刷新文字、留下旧图或旧结果的要报。
