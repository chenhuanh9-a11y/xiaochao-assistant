# Managed live runtime seam

`LiveRuntime` implements the existing `Core.Session.ISessionRuntime` and `IRuntimeRecoveryControl`. Construction is inert: no resource reads, round start, capture, window operations, input hooks, timers, or global listeners. The host supplies an already explicitly bound `ICapturePort` and a resource root. `set_context` binds the exact season/mode catalogs; `start_round` starts only runtime round state; `capture_now` or `map` explicitly starts frame acquisition.

The source path is `experiments/qt_quick/client_live_runtime.py` (`_dispatch_owned`, `_start`, `_capture_and_solve`, `_manual_action`, `_set_floor`, `snapshot`), `client_engine.py`, `client_manual_map.py`, `app/map_open_preparation.py`, and `app/fast_structure_alignment.py`. This is the available C# main-entry/native-fit path within the complete migration, not a claim that every original runtime branch is present.

## Host integration

```csharp
var runtime = new LiveRuntime(capturePort, resourceRoot);
var session = new SessionService(new SynchronizationContextSessionDispatcher(uiContext), runtime);
```

`ICapturePort` returns an owned immutable full physical client BGRA32 frame and `CaptureStamp(WindowIdentity, Generation, FrameId)`. Capture and native pixel copying require the target to remain foreground. The later `IsCurrent` read is bounded, thread-safe, and checks original window identity, geometry, binding/capture generation and frame lifetime; it deliberately does not require foreground, so switching to WPF to inspect or select a candidate does not revoke that capture. Input and overlay foreground authorization remain separate host responsibilities. Preview shares the binding/capture lane but does not replace the runtime's current stamp. Capture-port reads must not call the runtime or hold a capture-port lock while notifying it. After a binding, geometry/frame lifetime, resource instance or explicit map-close boundary, release capture locks and call `InvalidateCapture` / `InvalidateResources` as appropriate. These synchronous invalidations do not wait for active capture/vision work. The host independently owns binding, capture-port shutdown, Windows input and windows.

Call `Shutdown()` for final runtime closure; it revokes runtime state and rejects late frames/new dispatches without blocking or stopping the capture port. `ReadSnapshot()` / `ReadState()` return immutable bounded published state. A no-longer-current capture is withheld during reads without rewriting the runtime state. The only class that commits runtime identity, native pose, round or resource state is `LiveRuntime`, under its own state lock; capture/vision work is serialized and runs outside that lock. Its internal invalidation epoch is a runtime-lifetime guard, never a writer of the Core session generation or request sequence.

`set_context` payload accepts `season`, `mode`, `profileId`, optional `resourceRoot`, and `reloadResources`. `profileId` is an author/display preference only. Actual recognition references always use the current `EntryPassportCatalog.MapProfiles`, current target floor, and exact `ResourceCatalog` binding. Mode/resource rebinding requires an inactive round. Resource invalidation clears the round and bound resource identity; recovery requires explicit rebind/start.

## Current producer and consumer flow

1. Explicit context load uses the actual `ResourceCatalog.Load`, `EntryPassportCatalog.Load` and S0 identity pipeline or S1 structural catalog. It creates a new resource-instance identity only after successful binding and prepares immutable floor glyph resources outside the observation deadline.
2. Round start does not capture or enable global services. Capture before explicit round start is refused.
3. Map preparation follows the original 1.05-second deadline, 50-millisecond start-to-start probe cadence, delayed first probe for unlocked identity, immediate first probe for locked identity, and ceiling of 21 probes with the last probe scheduled near the deadline. Capture return and completed observation both recheck the same deadline; late usable pixels never become a prepared frame or reach rank/fit. These are correctness budgets, not measured first-visible-pixel performance. Current `FloorObservation.Observe` supplies map-open/floor evidence. No previous-frame floor fills an unknown current observation.
4. `set_floor { floor }` follows the original payload: null, missing, empty and `"auto"` clear the manual target; integer/string floors select it (`floorId` remains an alias for the new host). A manual target defers conflicting passive readings for the source's two-second hold. After that hold, the latest valid current reading releases the override; an unknown current reading does not invent history or silently expire an explicit target. `cycle_floor` requires an open map. There is no hard-lock/game-click-intent consumer in this runtime yet.
5. Unlocked S0 observations use the complete `S0IdentityRankPipeline` and `S0IdentityDecision` consumer: actual passport/main/side strategy, optional source advisory, native conditions, final rows and the explicitly registered front groups. A provisional registered group is reviewed on each new frame; its display member is never passed as a confirmed unique-map context. S1 scans the full target-floor catalog with original history scheduling hints; unsupported fits remain UNKNOWN and even a single positive candidate requires human identity confirmation.
6. Ordinary human map confirmation commits the exact catalog map immediately and survives pose refusal. The separate `select_group_member` action uses only registered members and a group-generation/cycle/floor scope. Its current member, pose and pixels remain intact while an independent candidate core fits the target and prepares material. `ReadPendingGroupMaterial` exposes that exact pending packet; after Session has collected the request, the WPF host consumes its BGRA into a frozen BitmapSource and calls `AcceptGroupMaterialReady`. That ACK commits the target identity, pose, grant, pixels and manual hold together. Rejection keeps the predecessor and desired intent; close/author/new-frame/resource boundaries reject old callbacks. A confirmed hold survives floor changes without rediscovery, while each floor fits independently. A current NONE withdraws an automatic provisional group but retains its unconfirmed desired member for a newly verified same-group retry. Material-ready is not a native-window/GPU-present ACK; later native failure withdraws display without undoing committed identity. Established condition-inventory review and RoundLayerGroup recovery/steady producers remain capability gaps.
7. S0 Fit uses `S0HostFit` with the actual same-frame entry candidate and target-floor resource; optional fast, entry revalidation, registered-floor and initial structure stages preserve source rejection order. S1 uses the shared current-frame structural pipeline. The only S0 prior comes from an earlier verified fit of the same resource instance/map/floor; S1 receives no prior. Other floors never seed a target's scale or transform. Missing optional stateful producers fail closed when requested, rather than being replaced with a successful cold fit.
8. Native geometry commits only if round/context/resource epoch, request cancellation and exact capture stamp remain current. Cancel, close, floor change, identity replacement, resource invalidation and shutdown revoke current pixels/pose. Closing a map preserves durable identity and per-floor trusted geometry; ending the round or resource replacement clears them.

Every operation receipt echoes the request context and the actual committed result context. `ReadState().NativePose` is native-reference-to-client geometry, separate from a canonical authorization. Actual residual/pack verification reaches AlignmentCore adjudication, authorization and commit before `TryReadRender` returns immutable selected-material pixels. Author preference changes may replace pixels without recapture or refit; unavailable pixels retain a valid canonical grant for explicit preference recovery. Close, cancellation or resource invalidation revoke that recovery. Recorded/Synthetic captures never receive LiveAuthorization. Published snapshots omit raw condition samples and pixel buffers; diagnostics and receipts are not display grants.

`ISessionRuntimeProgress.ReadSnapshotFor(request)` atomically returns a `SessionRuntimeRead` containing both the snapshot and its original admitted request's ownership of that exact snapshot. Both reads happen inside one Runtime state lock, with the original ticket, current epoch, cancellation and exact capture/window/geometry lifetime intact. A separate later ownership query is deliberately absent: the same worker can otherwise publish its next context between the two calls and accidentally cancel itself. `SessionService.RefreshRuntime` may publish the owned request's floor/frame/identity progress without cancelling the producer. The original request remains immutable; only its last accepted progress context is retained by the session. Final receipt echo/result-context/fresh-snapshot checks are unchanged.

The atomic result attests its read's linearization point, not a continuing pose/display permit. If an external boundary occurs after that point, the next refresh observes revoked ownership and the final result still must pass its fresh-context/capture checks. Once a request has accepted progress, losing producer attribution cancels it even if its visible context fields stay equal (for example capture revocation while the frame was already null). Before an operation has ever been attributed, ordinary context-change rules still apply. External resource/capture/shutdown epochs or a stale capture stamp revoke attribution; refused/stale admissions cannot claim another operation's snapshot. There is no accepted-history set, retry loop or widened epoch matching.

Final consumption independently performs the same atomic read before accepting any receipt or worker exception, even if no UI refresh followed revocation. Lost ownership is recorded as a stale `OwnershipRevoked` completion, with no `LastReceipt`; unchanged visible context is insufficient. Runtime settlement also verifies the original ownership and inner committed snapshot under the existing state lock. Valid settlement preserves the original inner receipt/result context and updates only the real settled snapshot; a revoked/context-changed operation cannot have its earlier success repackaged with a newer snapshot. This reuses the existing atomic protocol without another interface or lifetime mechanism.

## Remaining complete-migration work

The snapshot carries explicit capability gaps for side-entry ranking, original steady tracking/fallback, canonical/display bridges, author/custom route rendering, scheduled map-open recovery, locked-canvas remembered-floor reuse, and similarity-group competition. Missing resource contracts do not borrow another mode/season/floor. There is no saved-result/JSON pose import, alternative recognition shortcut, fake success, or automatic game input.

Default S1 additionally declares missing floor-vertical and structure-identity consumers, does not advertise automatic capture, and refuses a direct capture request with the specific S1-consumer gap before acquiring pixels. Changing `S1FloorUse` does not implement those consumers. The next S1 stage should bind the selected context's explicit manual/candidate capability, observe a new S1 current frame with the corresponding `FloorObservation` use, and feed a real full-frame S1 structure-candidate producer. A user-confirmed identity may then enter native fit using only that floor's resources. Automatic S1 identity requires that missing producer's actual current evidence and original consumer checks; current S0 results or a floor-use enum are insufficient. Canonical/display proof remains a separate subsequent stage.

The accompanying tests replace only capture/clock boundaries. Current frame observation, ranking, resource loading, native fit and all runtime state are actual C# production code. A post-2026-11-05 recorded capture is used as a numerical/runtime replay, never described as present live-window or game acceptance. See `tests/StarMap.Runtime.Tests` for the required arguments and output artifacts.

The reviewer regressions first failed against the original implementation in `full-csharp-validation/runtime-before-review-fixes`: the valid first probe returned late and was accepted, manual override did not expire, auto payloads were refused, and real `SessionService + LiveRuntime` middle-rank/middle-fit refresh cancelled its producer. The replacement clock controls only timing; actual post-2026-11-05 pixels and actual floor/rank/fit consumers remain in the tests. Additional checks reject expiry during observation, preserve the pre-expiry hold, revoke attributed progress after external resource replacement, and refuse default S1 without capture.

The initial tail-probe test had a separate stimulus error, preserved in `runtime-after-review-fixes-01` and `runtime-after-review-fixes-diag`: it required an unlocked session to execute probe 21, but the original delayed-first cadence produced only 20 starts and correctly reached the deadline with no committed frame. The source's final `max(next regular start, near-deadline start)` must not be changed to make that test pass. The corrected tail case establishes a legitimate human identity through the real confirmation API, which selects the source's immediate-first locked path; its 21st probe then returns late. It requires no new frame, candidates or pose, and exactly preserves the already-confirmed identity/resource/round. A separate unlocked all-black cadence case asserts starts .05 through 1.0, then the 1.05 deadline, with no 21st start. All prior failure evidence remains intact.

The subsequent deterministic progress-race evidence is retained in `runtime-before-atomic-progress`: the original 24 cases passed, while a real `SessionService + LiveRuntime` set-floor case failed. Its scheduling-only decorator obtained floor 2 / null-frame context A, released the actual capture worker, waited for the same request to publish context B / frame 2, then resumed the old separate ownership query. The recorded refresh cancelled itself (`Busy=false`, worker still active). The corrected regression preserves that actual producer advancement after the atomic read; four additional cases place capture/resource invalidation before or after that read and require the old result to remain rejected. These decorators do not replace vision, state, receipts or ownership decisions.
