# Agent 阶段结果转交格式（草稿）

这份格式供中台维护者审阅，当前没有接入运行规则或通道。

每个阶段结果是一条允许的 `xingtu.digest.item` 回执，包含：

- `id`：按任务稳定键与阶段生成，重试时保持不变。
- `subject`：`progress:<稳定键>:<阶段>`；不是 Dot 来源，也不伪装成 `dot.to-pip`。
- `summary`：事项、阶段、做成什么，以及必要的真实数字和限制。
- `detail`：测量边界、卡点、未验收项、下一步。
- `link`：相关 PR 或证据页面（可选）。

阶段取 `completed`、`measurement`、`blocked`、`owner-test`。本人实机测试请求保持 `ask:<稳定键>` 分类，进入每日汇总，不变成即时通知。只在接收通道确认成功后标记已送达；发送失败保留在 outbox，使用同一个事件 ID 重试。去重按事件 ID 做，不能把不同阶段合并。

启用前需要中台维护者在允许范围内将这个接收器接到开发回执流程，并提供一个明确接受 `xingtu.digest.item` 的 Pip 入口。现有每日汇总接收器只记账、既有转发只接受 `dot.to-pip`，因此本草稿不宣称已启用或已发给 Pip。
