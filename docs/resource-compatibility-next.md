# 下一版本资源兼容与迁移

## 基线与实现边界

- 已发布 1.1.1：`161e14f7d50b4c7ec27e2d29b67ecc060912da9c`。
- 本轮协同开发起点：PR #99 的 `1f3983bd0ac999671f31adc2f8df58cfe262a4d0`，不是重新定义已发布版本。
- 本文第一阶段对应本分支代码。第二阶段是尚未完成的后续设计，不能据此宣称任意图包已兼容。
- 云端验证使用临时文件、合成图包及离屏 Qt。未读取或改变玩家安装、游戏目录、真实图包和个人资料，未构建或运行 Windows Setup。

## 资源分层

1. **程序**：Qt 页面、算法和程序元数据。
2. **结构底模**：地图身份、楼层、结构与坐标基准、native 图及识别产品。仍由软件源代码审核的库存控制。不能因为移除作者路线图就一并删除困难结构底模。
3. **作者图包**：显示图片和绑定，受精确依赖闭包约束，不提供地图身份、结构校验或跨楼层权力。
4. **个人资料**：用户图片、路线、偏好、选择及手工编辑。不是安装包库存，也不是资源修复的清理对象。

下载的作者 ZIP 是否包含或引用底模必须读取其真实 manifest 才能判断。目前没有核对发行渠道实际 ZIP，不能假设下载作者包能补齐结构底模。当前第一阶段继续随 Setup 提供 S0 及 S1 困难/噩梦的已审核基础资源，作者显示图通过独立导入。

## S1 普通底模退役事务

历史审核库存 `s0-1.0.7+S1-native-2.104.3099014-20261106` 保持完整，继续用于解析旧安装状态和恢复日志。新库存版本为原版本追加 `-routes-only-v1`，只从历史精确库存减去 `_internal/seasons/s1/difficulty2/`，不改变其余 bytes 或 SHA-256。

源锁统计：564 项变为 372 项，去除普通 192 项、51,409,317 字节。这是未压缩文件总量，不是 Setup 最终体积承诺。

执行次序：

1. 在共享资源租约下完成待恢复事务处理。
2. 验证候选全部活动资源，读取旧所有权 manifest，确认恰好是上述受审迁移。
3. 汇总所有作者包所有权及有效依赖。V2 的普通层由源码固定为停用，其原依赖声明保留在收据中，但不再约束运行底模；所有活动层仍以候选平面验证精确闭包。旧协议中无法完整证明的约束继续保守保留。
4. 有引用、未知旧包或用户改动就整组延期；绝不部分删除普通层后丢弃旧所有权。
5. 对允许删除的精确旧文件记录 hash、大小及对象身份，并通过带来源/目标/完整退役清单的 v2 日志暂存旧对象。
6. 最后验证活动平面完整、所有已退役目标仍不存在，再提交新状态。
7. 提交前失败恢复旧对象和旧状态；恢复过程中发现新出现的未知文件则停止并保留它，不能覆盖。
8. 已提交事务只完成清理，不因清理失败重建旧数据。成功后保留有界审计摘要，不宣称永久保留可一键回滚副本。

该迁移不删除自定义图、导入作者图、偏好、路线或历史记录。普通文件原来缺失时也不会为了删除而重建。未审定的重命名、其他模式缺项、S1→S0 降级仍被拒绝。

## 不再内置困难作者图

- 生产 builder 拒绝 `--bundled-package difficult-zhan10`，生产输入中出现 S1 普通根也拒绝。
- 原有作者图资源分区仍将可选显示图片排除在 Setup 基础资源外。
- 生产运行不再读取 `qt-author-base` 作为作者默认，防止旧安装残留恢复“内置”显示。已导入用户图包照常保留。
- 本阶段不递归清理旧安装残留 `qt-author-base`，也不靠目录名称认领用户文件。新 Setup 不再携带它，旧安装磁盘回收应另做精确库存清理，不保证升级立即释放全部旧占用。
- 私测/历史资源工具仍可读取明确的旧资源输入，不因此获得生产打包资格。

## 提示与错误契约

`resource_compatibility` 只解释生产者的稳定错误码，返回诊断类别和建议，不授权导入、下载、修复或删除。缺失底模、不兼容底模、客户端协议不支持、绑定不匹配、所有权冲突、损坏包和无法核实收据分别处理。

错误详情仅保留受限相对资源路径，包括 S1 的已知基础目录；拒绝绝对路径、控制字符和目录穿越。V2 字段错误不再被冒号截断成泛化错误。

启动延期只向资源页传递状态和原因种类，不重复扫描资源、不增加阻断弹窗，也不把几百个路径暴露成提示。提示说明旧普通资源因历史依赖或本地改动保留，困难/噩梦已验证。

混合包处理不是删改 ZIP，也不是给普通绑定补一个“验证通过”。完整作者图片仍通过路径、大小、哈希、图片格式和尺寸校验；普通层绑定明确 `bindingVerified=false`，仅出现在派生的停用层摘要中。原绑定文件不改写，完整文件和依赖库存仍写入原格式收据。运行适配器只收到活动层；包自行添加的 `inactiveLayers` 或类似标志不能跳过活动层校验。普通作者文件仍由原包拥有，更新/移除/中断恢复必须覆盖它们。

这是源码定义的单一退役上下文投影，不是可由图包控制的通用“忽略错误”模式。活动层依赖被删减或损坏、普通作者图片损坏时，整个新包仍拒绝，不写入部分结果。

## 第二阶段：独立版本快照与有证据的迁移（未实现）

第一阶段仍有整体活动底模、同包不可缩减、不能自动迁移旧依赖等限制。完整解决需要以下独立任务：

1. 将基础资源、显示包、显示绑定拆成不可变版本快照，manifest 明确 `packageId`、内容版本、协议版本、赛季/模式/层及精确依赖。程序版本不能替代资源版本。
2. 单独索引每层激活状态：可用、缺基础、缺绑定、退役、损坏、冲突、待迁移。第一阶段仅支持固定 S1 普通退役投影；其他缺失/损坏层的通用隔离仍待新协议明确支持，不能把当前特殊规则扩成任意跳过校验。
3. 作者图片字节未变、可信底模迁移映射明确且几何契约可证明时，生成单独绑定版本；没有映射则保留旧快照，提示缺少哪一版绑定。禁止把相似图片或相似地图名称当兼容证据。
4. 更新流程先暂存完整包、验证依赖与空间、生成可预览迁移计划，再原子切换激活索引；旧快照按引用和用户选择清理。未知文件不纳入自动垃圾回收。
5. 对旧无完整收据的已安装包建立“保留但未验证”状态；只有原发行清单与实际字节完全一致才能生成可信记录。不能让用户点击一次确认就凭空生成作者/结构权力。
6. 提供逐包修复/替换/移除入口，明确受影响层、依赖包和可恢复范围。损坏包不连带阻断无关健康包，但仍不得提供未经验证的识别输出。
7. 下载目录提供基础包与作者包的真实分发契约、哈希和客户端协议；未拿到实际包验证之前不得宣称自动下载可补全全部依赖。

## 发版前检查与未知项

- 集成其他功能并固定版本后，重新计算生产 source payload 与 version 哈希。当前分支刻意没有重签旧哈希；生产构建应拒绝不一致源码，不可取消门禁。
- 使用授权真实资源根重新生成精确两模式资源清单，保留活动资源原 bytes/hash，完成最终组装树验证。
- 在 Windows 临时安装中验证新装、1.1.1 升级、用户旧图包、有改动普通底模、崩溃恢复、锁冲突和卸载向导。云端合成测试不替代这些验收。
- 新资源迁移完成后，直接换回旧 EXE 不等于安全降级。旧代码不认识 v2 退役日志，也可能要求普通资源；需要单独的回退包/恢复流程验证。
- 最终 Setup 大小、真实下载 ZIP 内容、真实图包与新资源组合、游戏内准确度均未在此分支实测。
