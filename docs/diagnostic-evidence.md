# 失败诊断证据导出

基于 `c3c53a4518d1049b0f1030646fb0c2151645ddc9` 的独立本地修改。

原导出只包含文字日志，排除了已在本机保存的失败画面；识别摘要还省略了特征数量、候选矩阵和缓存失败原因。未确认地图的 B1 采样也被拒绝。上述缺口会让“已经完成识别但没有确认地图”无法继续复核到输入像素。

现在“导出排查信息”在后台读取困难/噩梦及当前自定义存储根中的失败记录，按已导出日志的会话和时间范围关联已有样本。不会重新截图或重新运行识别。

- `diagnostic-manifest.json` 的 `failureEvidence` 列出每个案例对应的日志、cycle、楼层、元数据和画面文件。
- `evidence/NNN/failure.json` 保留实际采样时的完整失败判据；画面沿用原始无损文件，已有中间观察图也一起导出。
- 最多选最近 12 个案例，画面总量最多 24 MiB；每个存储根只读取最近 8 MiB 记录。超限、缺文件、损坏、无匹配样本和不完整记录均有明确状态。
- 当前采样状态随运行环境导出；跳过采样记录帧/轮次/界面代际失效、限频或队列状态，写入失败保留具体错误。
- 识别摘要补上已有特征数量、最低数量、评估地图、候选/验证矩阵、区域和墙体证据、结构特征缓存状态。仅增加诊断字段，不改变候选搜索、阈值或显示授权。
- 未确认身份的 B1 也可采样；使用该次 ranked 结果的快照，避免从引擎后来处理的另一帧取证。保留既有限频和磁盘预算。

导出按钮旁及完成提示明确说明可能包含游戏画面，分享前需检查。个人设置、确认训练记录和其他内存目录不打包；本地路径仍脱敏。直接调用 `export_safe_diagnostic_bundle` 而不传 `failure_roots` 时仍保持纯文本。

验证使用 Python 3.13.3 / OpenCV 4.12.0：诊断回归、侧门检索和入口预筛共 28 项通过，`git diff --check` 通过。诊断测试调用实际控制器方法、后台导出、失败存储器、ZIP 写入和图片解码；窗口环境/权限查询及采样 token 比较使用替身，没有创建 Tk 或操作游戏。

检查覆盖两模式 B1、像素回读、限频、迟到帧/关图拒绝、缺图/损坏/超限/路径越界/其他会话排除，以及写入预算耗尽的错误状态。源码和测试仅在独立本地分支；未合入主线、推送、打包或安装，不能声称现有 EXE 已具备此功能。旧导出包未携带的截图无法凭文字补回。
