# 失败诊断证据导出

本轮基线 `9b49db4`。改动模块为「游戏画面采集」「排查与帮助」，相邻「设置与主界面」仅更新帮助文案；「地图识别」「楼层判断」「路线贴合」的输入、算法和显示授权不变。

默认自动采样保存同次合法采集的**完整游戏窗口客户区**，保留原分辨率和原像素，不为遮挡游戏 ID、昵称或聊天裁剪、遮罩或缩小。默认诊断 ZIP 附上与日志会话及时间范围匹配的自动图片，不需要打开兼容手动采样。分享前请检查图片；可以关闭自动保存、取消附图或选择纯文字。旧设置明确关闭的选择继续保留。文字日志仍脱敏，不增加上传。

只复用通过绑定、前台、尝试、代次、取消、本局和当前帧校验的原始整帧；没有地图区、没有控件带、身份未确认或楼层失败都不再丢弃合法整帧。不抓桌面、其他窗口，也不为补图重新采集。失效、缺帧、超限或存储失败会留下明确缺失原因，不能当作已有完整证据。每次只写一张自动整帧，不再重复写地图图和控件图；自动采样开启时兼容手动写入器不重复保存。

- `diagnostic-manifest.json` 的 `failureEvidence` 列出每个案例对应的日志、cycle、楼层、元数据和画面文件。
- `evidence/NNN/failure.json` 保留实际采样时的完整失败判据；画面沿用原始无损文件，已有中间观察图也一起导出。
- 最多选最近 12 个案例，导出图片合计最多 64 MiB（四上下文共用，不乘以根数）；新自动图片单张最多 32 MiB，历史图片单张读取上限仍为 12 MiB。每个存储根只读取最近 8 MiB 手动记录；自动记录另有 256 KiB 有界 journal。超限、缺文件、损坏、无匹配样本和不完整记录均有明确状态。
- 当前采样状态随运行环境导出；跳过采样记录帧/轮次/界面代际失效、限频或队列状态，写入失败保留具体错误。
- 识别摘要补上已有特征数量、最低数量、评估地图、候选/验证矩阵、区域和墙体证据、结构特征缓存状态。仅增加诊断字段，不改变候选搜索、阈值或显示授权。
- `failures/automatic-v2/` 每赛季/难度上下文最多 6 张、图片合计 64 MiB、保留 7 天；S0/S1 × 噩梦/困难四上下文合计最多 256 MiB。优先轮换最旧的已证明归属的图来满足字节上限，不裁图或降采样。超单张上限则明确缺图。编码输入另有 64 MiB 原始像素上限。
- 原文件身份、单链接、尺寸、SHA256 与 Windows 独占句柄读取/删除保护保留。未知、变更或未提交图片失败关闭，不扩大清理范围。旧 `automatic` 局部样本只读兼容导出，各上下文历史最多 12 MiB 另计。
- 以上是新自动 PNG 的限额，不是整个目录的限额：文字日志、自动 journal、历史手动资料、旧局部样本、主动导出的 ZIP 均另计；ZIP 不受自动图片轮换清理。

导出按钮旁及完成提示明确说明可能包含游戏画面，分享前需检查。个人设置、确认训练记录和其他内存目录不打包；本地路径仍脱敏。直接调用 `export_safe_diagnostic_bundle` 而不传 `failure_roots` 时仍保持纯文本。

本轮验证记录见 [完整帧诊断检查记录](diagnostic-full-frame-validation.md)。模拟图的编码、Windows 原生文件句柄读写和离屏 Qt 检查分别记录，不代表已生成或安装新 Setup，也不代表真实游戏或当前安装已验收。旧导出包没带的完整画面无法补回。

接通反馈的前置验收：默认完整帧能够保存并随默认诊断 ZIP 导出，尺寸、四角/边缘像素和来源一致；绑定、前台、取消、关闭采样、纯文字、脱敏、四上下文及容量/过期检查通过；Windows 未测项逐项列清。缺少这些证据时保持未验收。本任务不接通上传、不上线反馈、不合并或发布；正式发布仍须 huan 本机验收。
