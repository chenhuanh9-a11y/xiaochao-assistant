# Inno Setup 替换提案：迁移、卸载与切换验收

本文是「安装与更新」的实施提案和验收说明，不代表 Inno Setup 已接管正式更新，也不代表迁移、全清卸载或发布流程已经上线。相邻可能受影响的模块是「地图资源」和「自定义图库」：安装迁移需要完整保留已安装图包及其依赖、自建路线和编辑器资源；卸载只清理本产品拥有的数据，不能误删外部原始包或其他产品的数据。

本提案按 huan 已选的“复用现有，卸载全清”执行：继续使用现有 Inno Setup 安装器；跨安装器升级时先迁移并验证资料，再切换程序；用户主动卸载时默认彻底清除本产品资料。本提案不启用发布列车或替换正式更新入口。

## 1. 新装、升级入口与资料迁移

| 用户当前状态 | 入口与前置条件 | 预期步骤与成功条件 |
| --- | --- | --- |
| 从未安装星图 | 启动同一提交构建的 Inno Setup；目标目录为空或不存在，磁盘空间满足安装和迁移暂存需要 | 安装程序文件和快捷方式；初始化必要配置。不得把默认识别资源种包作为升级资料恢复，也不得把空配置误判为迁移完成。 |
| 旧 QtIFW 版仍可运行 | 直接启动 Inno Setup，不要求用户先卸载 QtIFW。安装器只在确认旧安装身份、准确路径、账号和资料清单后继续；若实例不唯一、文件被占用、资料无法读取或磁盘空间不足，停止并保留旧版可用 | 在隔离暂存区复制设置、成套地图资源/图包及其依赖、自定义图库、自建路线和必要编辑器资料；逐项核对相对路径、文件数、大小、哈希及资源清单关系。核对通过后才切换程序和注册信息，并在新版本首次启动读取确认。验证失败时不删旧版、不清暂存、不宣称升级成功。 |
| 已由旧 Inno 版安装 | 使用新 Inno Setup 的覆盖升级入口；确认产品身份、目标根、运行进程已退出、没有未完成安装或资源事务 | 复用现有 Inno 升级协调和原生升级入口；保留已有设置、成套地图资源/图包、自定义图库和自建路线，按统一迁移清单校验。不能因为路径相同或文件名相同就跳过哈希及归属核对。 |
| 新 Inno 版之后的跨版本升级 | 启动更新版本的 Inno Setup；只接受同一产品身份的受支持来源版本，先识别安装清单与迁移状态 | 先核验程序和用户资料现状，再按版本迁移规则逐版处理；新版本完整核验前保留可恢复资料。版本跨度不受支持、清单损坏或迁移不完整时停止并给出恢复指引，不自动卸载或清理旧内容。 |

旧 QtIFW 跨安装器升级不能走“先彻底卸载、再新装并自动找回资料”的路径：全清卸载会删除可迁移的资料。迁移须由新安装器或其受控助手在旧资料仍可读取时完成，先复制、校验、再切换；未经确认和完整回执不得删除旧来源。运行中的旧程序、启动监听器和持有资源锁的进程必须按既有安装合同安全停止，失败就保留现场并退出。

成套资源的校验不能只验证每个文件各自可读：须按地图资源清单验证包身份、版本、依赖及载荷哈希，并确认迁移后仍能被资源目录读取；自建路线另核其用户归属与内容。恢复后分别启动程序、打开资源页和自定义图库检查，不能把“文件已复制”当作迁移完成。不得恢复默认种包，也不得把构建输入清单当成用户安装资源。

## 2. 用户主动卸载：默认彻底清理

从 Windows 应用列表卸载、开始菜单卸载入口或安装目录卸载入口发起时，默认行为是彻底卸载星图并清除其所属资料，不提供“保留资料”选项。卸载开始前显示清理范围和不可恢复提示；用户取消则不执行清理。静默卸载也采用已选的全清策略，但必须只触及当前星图安装身份明确拥有的对象。

清理范围包含：

- 当前安装目录中的程序、运行数据、设置、缓存、日志、下载内容、编辑器底图、地图资源/图包、自定义图库、自建路线、备份副本和迁移/卸载暂存资料。
- 已核实属于本安装身份的 AppData、LocalAppData、ProgramData 下星图数据目录，包括配置、缓存、资源、图库和暂存；按实际安装清单发现，不凭产品名猜路径。
- 本产品精确的注册表卸载登记、安装器维护/修复入口及其所有权标记；本安装创建的桌面和开始菜单快捷方式、开始菜单目录；本产品的启动项和游戏启动联动入口。
- 旧 QtIFW 安装残留的维护工具、维护器入口及专属卸载登记。仅在通过旧版产品身份、精确路径和归属记录核实后清理；不能运行一个未知维护器替用户执行广泛删除。
- 为本次迁移或卸载创建的备份暂存和恢复暂存。清理前核对其事务归属和内容清单，避免删除用户另行复制到相邻目录的资料。

清理时先停用并退出本产品的启动监听器，确认星图进程及资源事务已结束；再由原生卸载入口清除安装文件、资料和准确的快捷方式/注册表对象。遇到锁定、权限不足、未知文件、损坏事务或身份不匹配时，逐项报告未清对象，不扩大目录范围，不把部分清理称为彻底卸载。只有所有权和删除结果均可验证，才报告成功。目标目录外的用户文件、其他 Windows 账号资料、其他产品资料、外部原始 ZIP 和未确认归属的相邻文件不在范围内。

## 3. 测试/正式 Setup 输入、下载、切换和回退

一次候选只使用同一个远端提交作为源码、版本清单、测试 Setup 和正式 Setup 的输入。构建记录应固定完整提交编号、产品版本、构建工具版本、输入清单摘要和干净源码状态；候选登记包含文件名、字节数和 SHA256。正式候选须由同一已验收源码提交重新构建或由该提交产物按既有正式构建合同生成，不能拿测试包改名冒充正式包。Setup 的体积只记录实测值，不承诺体积收益。

网盘交付由 huan 在浏览器中下载候选 Setup。下载后先核对页面显示的候选名称/版本，再在本机对落地文件核对字节数和 SHA256 与候选登记完全一致；不匹配、下载中断或来源不明时删除本次未验候选并重新取文件，不运行它。测试 Setup 与正式 Setup 使用清晰不同的名称、版本标识和交付记录，测试包只在隔离 Windows 环境、专用测试账号及专用安装目录中使用，不触碰日常安装资料。

切换正式更新入口前，至少满足：代码测试、Inno 编译检查、隔离新装/覆盖升级/卸载、QtIFW 到 Inno 迁移与资料核对均有同一候选的证据；旧残留根因已核对；历史包接管范围明确；PR/整合分支所需检查通过；huan 在自己的 Windows 电脑完成正式候选验收。未满足任一项时，旧入口继续作为当前入口，不能将提案或测试包发布为正式更新。

切换仅允许按明确产品身份逐步启用，并记录旧入口、候选版本、开始时间和回退条件。若升级前置检查失败，直接取消并保留旧安装；若复制或哈希核对失败，不切换并保留旧资料；若程序切换后新版本首次启动或资料读取验证失败，停止新版本继续写资料，保留迁移源和事务证据，按经过验证的恢复步骤回到可启动状态。未证明新旧程序及资料状态完整前，不得清理旧程序、旧资料或恢复点。不存在已验证的回退证据时须暂停切换，由 huan 处理；不得以强制覆盖或手动删除绕过。

本提案不修改发版列车、网盘文件或线上公告，不上传、不签名、不购买，也不创建正式版本或标签。

## 4. 验收矩阵与证据格式

| 阶段 | 必查场景 | 通过证据 | 不能据此宣称 |
| --- | --- | --- | --- |
| 代码测试 | 升级协调、卸载范围、启动联动、更新服务，以及迁移清单和失败恢复 | 测试命令、完整输出、通过/跳过/失败数、提交编号 | Windows 原生安装、真实资料迁移或正式验收通过 |
| 编译 | `tools/verify_installer_compile_only.py` 对最终候选输入执行编译检查 | 完整提交编号、工具版本、输入清单摘要、编译结果和产物大小/哈希 | Setup 已安装、可覆盖真实旧版或可以发布 |
| 隔离安装/卸载 | Windows 专用虚拟机/测试账号：新装、旧 Inno 覆盖、旧 QtIFW 跨版本升级、各类故障中断恢复、彻底卸载；使用合成设置、成套测试图包和自建路线，外置哨兵验证边界 | 每个用例的环境和前置版本、Setup 哈希、操作步骤、逐项前后清单与 SHA256、进程/注册表/快捷方式观察、失败注入点、日志和最终状态 | 真实用户资料已经安全迁移或正式候选已被本人验收 |
| 本人正式验收 | huan 在自己的 Windows 电脑核对正式 Setup、新旧版本升级、资料读取和彻底卸载告知；正式卸载只用明确批准的专用资料副本 | 本人验收日期、候选提交/版本/大小/SHA256、结果、未通过项与处理决定 | 其他提交、其他包或后续发布候选自动通过 |

证据按“用例—候选身份—前置条件—步骤—观察结果—结论”记录。每条结论必须绑定实际测试的完整提交、Setup 文件哈希和环境；保留失败输出与跳过原因。隔离合成资料必须标明合成，不使用真实用户目录，不把截图或模拟测试说成已验证游戏内行为。

本任务之后的代码验证清单仍须由对应实现任务执行：`test_installer_upgrade_coordinator`、`test_uninstall_data_wizard`、`test_game_startup`、`test_update_service`、`tools/verify_installer_compile_only.py`，以及实际迁移和 QtIFW 回归。代码测试、编译、隔离安装卸载和 huan 本人正式验收分开记录；本提案没有执行或冒称通过这些检查。
