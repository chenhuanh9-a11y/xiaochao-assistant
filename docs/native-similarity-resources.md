# 原生相似地图组资源

全库正门接入使用条件索引 v2，重点记录从正门进入后随探索扩大而持续或解除的结构歧义。侧门小范围相似关系不进入默认组资源，原侧门识别保持原有职责。下面保留的显式成员生成器用于已有 v1 资源。资源提供结构候选和差异证据，不代表唯一地图身份或可信贴合变换。作者攻略图仍只是显示层。

## 全库正门条件索引

先安装 `tools/maps/requirements-maps.txt` 中的离线工具依赖，再对完整资源根执行：

```powershell
python tools/maps/scan_similarity_catalog.py <完整资源根目录> --output-root <新的空扫描目录> --kind front
python tools/maps/scan_similarity_catalog.py <完整资源根目录> --output-root <扫描目录> --differences-only
python tools/maps/build_similarity_conditions.py <完整资源根目录> <扫描目录> --output-root <新的空候选目录> --kind front
```

以扫描器的 `--help` 为准；试点的 `--pair-limit` 和差异采样限制只能用于开发检查，不能代表完整资源。正门扫描按模式、楼层枚举全部地图对，保留每个方向的状态。缺少资料、没有足够结构、不适用和在已扫描条件下不兼容分别记录。旧的整图及侧门分析可保留作诊断，生成器只消费正门条件，不将其并入默认运行时组。

比较使用固定每单位 60 像素、无旋转的正门对齐种子，以及入口中心半径 1、2、4、8、12 单位的嵌套正结构方形窗口。半径不是游戏行走距离；按实际持续范围报告关系，不设置任意的长期组筛选阈值。可见正结构需要得到对应结构支持；窗口外结构或未观察区域不作为负证据。这是有限静态观测条件的清点，不能推导任意雾区视野的识别正确性。较大窗口新增候选导致成员集合不单调时，探索结论保持未知；个别地图对的定向扩窗诊断不能冒充新增半径下的全库竞争。

v2 索引分别保存参考、观测域、位姿、半径条件和逐位姿对差异。仅完全相同的变换合并，多位姿不能按地图 ID 覆盖；相交的条件集合不做传递闭包。相同观测域、位姿对和坐标点的证据可跨半径累计，模式、楼层或资源变化时清理。生产路径保留原识别门、必要竞争及计算预算；未完整观察、竞争不完整或超时不能产生优先结论。

入口条件只决定哪些候选及位姿成立。后续差异比较覆盖这些既定候选在入口坐标中的完整正结构范围，不能再次裁到仍相似的小窗口，否则恰好会丢掉远处可区分的房间。离开入口后，只有可信的当前帧位姿才能投影这些差异；看不见、未探索或没有可信位姿时保留未知，不把缺少像素当反证。完整正结构仍被另一地图包含时，也不保证仅靠新增正证据就能唯一确定。

运行时接入要求：一楼合法正门组建立后，立即通过正常地图选择入口暂选一个稳定组员，原唯一身份硬门保持真实。暂选成员使用原当前帧贴合与显示校验；首次贴合失败保留选择，等待重新开图。关图再开图后，已锁定流程也继续消费组内证据，必要时切换成员并重新验证当前帧变换。二楼首次侧门识别独立处理，不从一楼继承组、尺度或变换。

差异采样先比较原始源像素中心与目标像素中心，再投影并检查落盘整数采样点；两者均须超过原 3 像素容差，最多 512 点的采样策略不变。索引记录 `distanceEvaluationSpace=original-source-and-target-positive-pixel-centers` 与 `persistedSampleDistanceChecked=true`，避免把源图重采样的取整误差当成真实结构差异。

生成器只输出两个新增文件：`references/native-similarity-groups.json.gz` 和 `references/native-similarity/condition-samples.npz`。JSON 使用无损 gzip，全部条件与采样保持不变。运行时优先读取存在的压缩索引，缺失时兼容普通 JSON；压缩文件损坏会报告资源错误，不回退到可能过期的普通索引。

将两个新文件加入匹配的完整基线，保留原地图注册和共享结构索引；不要用某个试点子集替换完整包。旧结构若只有参考图坐标而没有原生世界映射，只能参与有依据的局部比较，不能伪造整图世界坐标关系。文件压缩只减小交付体积，实际冷初始化、内存和开图预算须用完整资源分别测量。

## 显式成员资源 v1

`tools/maps/build_native_similarity_groups.py` 从已绑定版本与楼层的共享结构 NPZ 生成相似组资源。它不重新提取游戏包体，也不使用作者攻略图。输入的 alpha footprint 只表示渲染结构占据的像素，不表示语义墙体、可行走区域或当前可见区域。

以同一原生坐标空间的三成员一楼为例：

```powershell
python tools/maps/build_native_similarity_groups.py <完整资源根目录> --output-root <新的空候选目录> --member nightmare-04 --member nightmare-12 --member nightmare-19 --profile zhan10-speed --floor 1 --variant variant-01 --group-id native-04-12-19
```

生成器要求各成员有明确的原生世界边界、等比例像素尺度及单位渲染器转换；不能用作者画布尺寸推算结构坐标。输出记录成员的 mapId、楼层、结构版本、源版本、依赖文件内容和原生到组画布转换，包含所有无序成员对的正向差异掩码。其他楼层必须独立生成，不能继承一楼变换。

候选目录包含选中成员的参考文件和精简 shared index，方便独立回读；**不能把整个目录覆盖到完整资源包**。CLI 输出的 `completeBaseIntegration` 明确区分：

- `newFiles`：要加入匹配完整基线的分组索引和差异 NPZ。
- `referenceDependencies`：必须在完整基线中核对内容与版本的原生参考。
- `preserveBaseFiles`：必须保留的完整 shared index。
- `candidateOnlyFiles`：候选自含依赖，不作为完整包替换内容。

接入前复制完整基线到独立测试目录，核对参考依赖后只加入 `newFiles`，再从实际生产资源根加载。应回读新增文件，并确认完整 shared index 与基线逐字节一致、未参加本组的地图仍然注册。生成候选和文件回读只证明资源构建，不证明生产识别、组状态切换、可见贴合或实机体验已通过。

游戏资源、实际玩家截图和诊断日志留在受控的本地证据目录；源码仓库仅保存生成器和合成 fixture 测试。
