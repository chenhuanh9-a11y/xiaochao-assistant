### 已证明的限定事实

同一台 Windows 11 机器、同一张真实录制画面、同一 WPF 实验壳、同一资源快照和多进程二进制管道条件下，仅替换局部网格计算取得约 70 毫秒热路径收益，总工作集中位数约增加 73 兆字节（二进制单位）。这不是正式 Qt 客户端成绩。

| 指标 | 原 Python 链 | 局部 C# 网格 | 无 Python 的 C# 实验链 |
| --- | ---: | ---: | ---: |
| 贴合计算热中位数（毫秒） | 182.5 | 111.5 | 169.1 |
| 端到端热中位数／第95百分位／最大值（毫秒） | 350.3／361.7／366.0 | 278.1／285.0／288.4 | 336.8／433.9／449.8 |
| 全进程树工作集中位数（兆字节，二进制单位） | 437.4 | 510.0 | 645.5 |

每路线为六次新进程首次请求及102次热请求；百分位采用最近秩法。局部方案贴合中位数减少71.0毫秒，端到端中位数减少72.2毫秒，工作集中位数增加72.6兆字节。工作集可能重复计算共享页，采样最大值也不是瞬时峰值；提交量不能当成实际内存。

报告中的端到端从截图开始，到状态、结构和透明像素经屏幕回读确认结束，不包含截图前等待，也不等于真实游戏按键到显示。每路线108次成功、无失败和缺失回读；保存的36份完整结果非计时字段严格一致，保存的图像逐像素一致，36幅屏幕结构区域差异为零。其余轮次只有计时和状态，不能声称324份完整结果均已比较。

范围仅为 S0／噩梦／二楼初次识别实验路径。楼层为配置输入；不能据此证明自动读层。完整 C# 实验链冷启动较快，但初始化范围、运行时和原生库不同，不能把差异全部归因于语言；其热尾延迟和工作集更高，不能据此推荐全面迁移。

## 四、可切回原 Python 实现的开关

拟议设置为“计算后端：原 Python／局部 C#”，名称仅示意，当前没有新增配置。默认原 Python；缺配置、值无效、候选组件缺失、握手失败均走原实现。原算法与依赖必须保留，不能只留一个无法启动的名义回退选项。

切回时先使旧请求代际失效、撤销旧显示和待提交结果，再取消候选任务并有界结束所属子进程；后续有效帧用原 Python 路径重新计算。不能将已过期输入直接重放成当前结果。候选故障后本次会话锁回原后端，不自动反复试探；重新启用须显式选择并重新握手。开关切换、重复切换、退出和重启后的默认行为均列入①②⑤验收。

## 五、可靠性设计

以下是待实现、待验证的协议和生命周期约束，不是现有能力声明。

- 请求含单调请求序号和进程会话代际，绑定实际相关的帧／页面代际、对局、模式、地图、楼层、资源版本及显示来源。重启后不能复用旧会话身份；应答必须原样关联请求。
- 状态写者在提交前核对当前请求及上述相关身份。关图、换图、换层、结束本局、退出或资源更新立即撤销旧任务资格；迟到、乱序、重复和旧进程结果直接丢弃，不能重新显示或确认旧路线。
- 每请求设有界截止时间，具体值在测试前约定。超时先撤销资格再取消任务；队列与隐藏图片结果有界，不能无限堆积或等待。回退计算也受当前上下文和截止策略约束。
- 检测进程退出、管道断开及请求无响应；故障撤销全部关联任务。重启采用有上限的退避和次数预算，退出时不再重启；重启只恢复可用性，不自动切回候选。具体退避及预算由验收方案确定。
- 建立协议版本、组件构建身份、资源契约与能力握手。版本不匹配、响应格式或尺寸非法、缺少模式／楼层能力时拒绝候选，明确报告能力缺口，不猜测兼容。
- 后台负责推进、取消与收取，不依赖页面可见性；最后的显示提交在 Qt 界面线程执行。恢复窗口或切页补当前状态，保持稳定页面实例、选择、焦点和滚动。缓存绑定实际资源及渲染来源，更新资源同时失效对应缓存和旧任务。

识别与贴合核心仍由共享链路负责，噩梦与困难通过资源和参数表达差异；不复制两套算法。结构证据决定身份和位姿，作者显示不得隐式改变它们。

## 七、打包、升级与玩家资料保护

现状对齐依据为[开发流程](development.md)、[QtIFW 真实试用记录](development/qtifw-real-trial.md)和[隔离原型说明](development/qtifw-windows-prototype.md)。仓库 Qt 客户端相关链路位于 `experiments/qt_quick`，其中运行、会话与资源模块应在未来接入时沿最终消费者核对；目录名不代表实验成绩已经覆盖正式入口。

QtIFW 试用采用默认保留资料、清理需明确选择的方向；其合成资料与隔离安装证据不证明真实玩家资料迁移完成，也不表示正式安装链已被替换。本方案保持“卸载默认保留资料；清理需确认”，取消则不清理。未知文件、外部路径、恢复副本和用户自建地图不得因程序组件卸载被顺带删除。

迁移原则是**先复制、再校验、再切换；永不自动删除旧原件**。先识别真实资料路径、资源租约及未完成事务，停止相关写入；复制地图、路线、设置和必要导入记录至独立暂存位置，核对文件清单、字节及哈希，再验证新版本可读取且语义一致，最后切换资料引用。任一步失败停在旧版本和旧原件；新格式不能原地覆盖旧格式，回退不得让旧版读取未经验证的新格式。

混合包保留 Python 环境及其原生依赖，同时明确 C# 所需 .NET 和原生库版本。选择随包运行时还是受控前置安装、位数与版本锁定方式须先确认；不能依赖开发机碰巧已有运行时。安装须检查组件齐全、版本匹配、授权与来源，握手成功前不切换。分版本暂存完整组件集，以可恢复的激活记录切换；中断后核验恢复旧集，禁止半新半旧。存储不足、文件占用、权限失败和依赖安装失败均列入⑤。

交付仅使用 Setup。未来若另获授权准备交付，应绑定同一最终远端提交的干净构建，记录版本、来源、资源锁与哈希、产物字节数及校验值和未测项；构建、安装、实机验收及发布分别记录。本次不构建、不安装、不覆盖玩家目录。
