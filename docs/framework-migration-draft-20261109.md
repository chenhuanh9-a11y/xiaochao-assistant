## 二、证据与边界

本文阅读了指定本地报告、验收评论文本、独立核查摘要及原草案。独立核查摘要是经 Pip 转述的核查要点，不等于本次执行独立复现。下列数字均来自固定提交的报告，本次没有新增测试。

### 已证明的限定事实

实验条件是同一台 Windows 11 机器、同一张录制帧、同一 WPF 实验壳、同一资源快照及多进程二进制管道，仅覆盖 S0／噩梦／二楼初次识别路径。楼层由配置输入。

| 指标 | Python 原链 | 局部 C# 网格 | 无 Python 的 C# 实验链 |
| --- | ---: | ---: | ---: |
| 贴合计算热中位数（毫秒） | 182.5 | 111.5 | 169.1 |
| 端到端热中位数／第95百分位／最大值（毫秒） | 350.3／361.7／366.0 | 278.1／285.0／288.4 | 336.8／433.9／449.8 |
| 全进程树工作集中位数（兆字节，二进制单位） | 437.4 | 510.0 | 645.5 |

每路线六次新进程首次请求、102次热请求，百分位用最近秩法。局部网格计算热中位数少71.0毫秒，端到端热中位数少72.2毫秒，工作集中位数多72.6兆字节。无 Python 实验链热尾延迟和工作集更高，提交量较低；不能将提交量当实际内存，工作集也可能重复计入共享页。

实验端到端从截图开始，到状态、结构和透明像素经屏幕回读确认，不含截图前等待，不是真实游戏按键到显示。各路线108次成功，无失败和缺失回读；保存的36份完整结果非计时字段严格一致，保存图像逐像素一致，36幅屏幕结构区域差异为零。其余请求仅有计时和状态，不能称324份完整结果均已比较，也不是324张独立地图的准确率。

无 Python 实验链启动到首结果更快，但初始化范围、.NET 运行时与原生 OpenCV 版本不同，不能把收益全部归因于语言。现有数据没有分配、垃圾回收或系统调度追踪，不能断言尾延迟原因。

### 未证明及不可外推项

单图 WPF 实验壳局部加速，不等于正式全量迁移已验证。真实游戏、正式 Qt 客户端、自动读层、其他地图／模式／楼层、混合显示器缩放、执行中取消、并发重入、长期内存／句柄、崩溃／超时／迟到恢复、安装／升级／回退及双运行时依赖均未验收。安装包收益和“约 1/3”均未验证。

C# 实验仍有身份凭据、已知通道、恢复消费者及其他模式／楼层能力缺口。不能填假资源、降低门槛或绕过消费者凑齐覆盖。原始私有帧、完整工具源码和构建配置未随报告公开，克隆报告不能独立复现；后续须补齐获授权的复用输入、脚本及构建配置。上述限制保留，但不改变尝试 C 的主决策。

## 四、目标架构与选型

目标为 C# 客户端、应用会话与任务调度、共享识别／贴合核心、资源与显示来源适配、资料事务和安装更新边界。UI 不拥有识别真值，业务层拥有对局与资源身份；计算返回候选结果，经当前上下文验证后才能提交到显示。

噩梦与困难共用识别、首次及后续贴合、楼层切换、正门／侧门策略、排队取消及提交核心；差异用资源提供器、楼层元数据、坐标契约与必要参数表达。结构证据决定身份和位姿；作者图、自定义路线只负责显示，每层显示桥绑定实际来源，包括结构回退层。相似组只移植已明确复核登记的成员表，未登记地图独立；缺权威名单报告资源缺口，不合成生产成员。

### UI 框架比较

| 选项 | 优点 | 代价与本项目取舍 |
| --- | --- | --- |
| WPF | Windows 桌面体系成熟；已有实验用过 WPF，可复用已理解的显示与管道接缝 | 仅面向 Windows；透明覆盖、点击穿透、混合缩放、绘图尾延迟仍须正式验收；实验壳不是完整客户端基础 |

| Avalonia | 提供跨平台 UI 路径，适合确有多平台计划时评估 | 当前游戏采集与全局输入依赖 Windows；跨平台 UI 不自动移植这些能力，还要验证渲染、原生互操作及分发依赖 |

**huan 已确认采用 WPF。** 理由是现有 Windows 目标及实验接缝可降低起步成本；正式客户端当前为 Qt，页面、输入、显示和生命周期都需按实际入口迁移，不能把 WPF 实验的成绩当作框架胜出证据。没有三框架同条件基准，不给出速度或包体排名。若以后出现明确跨平台目标，再重新打开选型，不在这三条决定里。

### .NET 打包比较

| 方案 | 体积与部署取舍 | 兼容门槛 |
| --- | --- | --- |
| 自包含（self-contained） | 随包带指定运行时，干净机器依赖更可控；下载与安装占用可能更大，运行时安全更新需纳入组件维护 | 锁定目标架构、运行时和原生依赖，不能假定带运行时就无需检查系统条件 |

### 阶段一具体工作项

后续开工按以下清单执行。阶段一工程在独立分支，不在本计划分支里改产品代码。清单本身仍然有效；合成帧或未完成的 Windows 验收不能算清单已经通过。

1. 固定现版源码／发布包身份、资源锁和哈希，记录正式 Qt 入口、环境及依赖。将识别计算、UI 启动、资源操作、安装升级分成独立测量边界。
2. 沿“入口 → 状态写者 → 页面／缓存 → 后台任务 → 最终消费者”建模块移植映射，标识两模式调用、恢复消费者、身份凭据和已知通道等实验缺口，明确每个状态的唯一写者。
3. 整理获授权录制帧及资源，绑定地图／楼层真值、输入来源和哈希；含正常、模糊、黑帧、拒绝显示及恢复序列。私人素材留在授权位置，共享材料只含脱敏摘要；缺素材明确登记。
4. 固定 Python 对照输出结构：候选、身份、接受／拒绝、楼层、位姿、残差、路线及渲染来源。识别逻辑、分支与阈值一比一移植，不做算法优化；先采用严格比较。若底层数值必须有容差，须在运行前有依据并确认，且不得改变接受判断，不能跑完再放宽。
5. 在独立实现分支建立所选 UI 的最小正式入口骨架、会话代际、请求序号、截止时间及结果提交器；临时 Python 对照工具仅用于验证，不成为最终 C# 产品的隐藏算法依赖。
6. 打通一条录制帧到最终可见结构的 C# 纵向链，核对当前帧确实参与求解，明确这不覆盖完整模式。补同一链的黑帧清除、恢复、取消、旧会话和乱序结果拒绝。
7. 用同一批输入执行 Python／C# 对等比较，记录实际命令、工具版本、构建参数、输入哈希、逐项差异及替身边界。分别计计算和可见终点；不能得到终点就写未知。
8. 建立可重复的发布配置体积与启动测量步骤；原型缺模块或资源时只记原型值，不宣称完整包收益。将六项目标预算、故障超时和长期观察窗口提交确认，供后续阶段使用。

每阶段验收表填写版本、环境、步骤、预期、实际、证据和未覆盖项。首贴与锁图后每次重开分开，记录连续样本数量、中位数、第95百分位、最大值、失败／未显示次数及有图像真值支持的错层次数，说明百分位方法。约500毫秒首贴、约300毫秒重开是仓库目标，不是已达成绩；缺真实输入时刻或真值不得补算成功。完整进程树资源分别记录工作集、提交量、CPU、句柄及长期增长，不能只测主窗口。

## 六、热键、状态与可靠性

**不吞系统键，保持现有输入穿透契约。** 全局输入不由窗口内快捷键替代；独立消息循环观察输入并继续向系统／游戏传递，业务拒绝不能拦截原键。局外地图键不隐式开始本局，不采集、不识别；等待游戏时管理快捷键仍有效。局内关图重开保留身份，显式开始与结束遵守原状态门；迁移不重置真实开关相位，不借机改键义或识别阈值。验证前台校验、释放、重复触发、停止监听及线程退出。

以下为待实现契约：

- 请求带单调序号和会话代际，绑定实际相关的帧／页面代际、对局、模式、地图、楼层、资源身份及显示来源。即使全部进程内运行，也使用会话代际与取消令牌隔离旧任务；取消令牌不能代替提交前再验身份。
- 关图、换层、换图、结束本局、资源更新及退出立即撤销旧结果资格；超时、乱序、重复、迟到和旧会话结果丢弃，不能重新显示或确认。超时先失效再取消，队列与隐藏图片结果有界，具体预算测试前确定。
- 后台任务推进、取消、收取不依赖页面可见。仅 UI 线程写控件；页面和卡片实例／标识稳定，重复选页幂等，普通状态变化只更新所属区域。恢复窗口补最新状态，保留选择、焦点和滚动，缓存绑定实际资源和渲染来源。
- 若保留采集／原生计算／导入 helper 等多进程，建立协议版本、组件构建身份、资源契约、能力握手和就绪确认；缺能力或版本不符明确拒绝，禁止混用新旧组件、伪造资源或放宽验证。
- 多进程监测退出、通道断开与无响应，撤销相关请求，按有上限的退避与次数预算重启；退出时禁止重启。新进程须重新握手，只接收当前有效的新请求，不重放过期帧。
- 进程内不可隔离的原生崩溃由下一次启动检测异常结束、提示恢复并保留旧版入口；不承诺进程内自动恢复。若有外部监督器才允许有界退避重启，不能形成重启风暴或反复开启游戏采集。

## 七、安装升级、玩家资料与依赖

沿用[开发流程](development.md)、[QtIFW 真实试用记录](development/qtifw-real-trial.md)及[隔离原型说明](development/qtifw-windows-prototype.md)的资料保护方向。QtIFW 的隔离试用和合成资料证据不代表真实玩家资料迁移已通过，也不表示正式安装链已替换。

**先复制、再校验、再切换（copy-verify-switch），永不自动删除旧原件。** 识别真实地图、设置、路线、导入收据及未完成事务，暂停相关写入，复制到独立暂存位置；校验清单、字节、哈希及新版本读取后的语义，再以可恢复的激活记录切换引用。新格式不能原地覆盖旧格式，不能让旧版读取未经验证的新格式。失败保留旧引用与原件；新版本产生的资料另存，回退时不可直接覆盖旧资料，需另行核验可兼容副本。

与 QtIFW keep-data 方向一致：卸载默认保留资料，清理需明确选择与确认，取消不清理；迁移旧原件不属于自动清理范围。未知文件、外部路径、恢复副本、用户自建地图及接受／拒绝记录不能随程序组件删除。存储不足、文件占用、权限失败、资料损坏和断电恢复均须有明确失败结果，不冒称迁移成功。

双栈并排期分版本目录、入口与完整组件集，旧版保留 Python／Qt／原生依赖，C# 保留其匹配的 .NET 与原生库。禁止从开发机环境隐式借依赖，禁止共用可被另一版本覆盖的组件目录；共享资料只读或用明确写入租约，不能让两栈同时写同一份资料。临时 Python 对照工具和可能的 C# helper 分别登记，最终全量候选须核查不存在未申明的 Python 算法回退。

新版本安装到独立位置，完整核验依赖、资源与协议后才切换入口；中断依据持久事务恢复旧完整版本，不能留下半新半旧。依赖框架包需验证缺运行时、离线环境、安装失败及版本不兼容；自包含包仍需验证原生库和系统条件。并排期总磁盘成本应单列，不拿最终单栈估算掩盖临时增长。

软件交付只用 Setup。未来若获授权交付，针对性检查和构建绑定同一最终远端提交，在干净检出中构建，记录版本、来源、构建参数、资源锁／哈希、产物精确字节数、SHA256及未测项。构建、安装、实机验收和发布分别记状态；本次不构建、不安装、不覆盖用户目录。

## 八、并排期与回退

现版继续发布，直到 C# 通过验收；C# 候选独立并排，不自动替换现版。对照使用同等功能、资源与输入，真实游戏操作及安装须在后续明确授权范围内进行。离线回放、源码检查和模拟输入均不能称为真实 GUI／游戏通过。

| 失败情形 | 处置与最终要求 |
| --- | --- |
| 候选结果不等价或缺能力 | 停止该链路显示，保留明确差异；现版继续承担使用，不修改识别阈值掩盖问题 |
| 超时、迟到、关图／换层 | 先撤销请求资格，再取消；不显示上一请求路线，不无限等待 |
| 子进程崩溃或协议不符 | 失效相关任务，按预算恢复或停止候选；不能自动重放旧结果 |
| C# 整体崩溃或候选不可用 | 使用保留的旧版独立入口和核验过的旧资料；不是假设 C# 内部一定存在 Python 后端开关 |
| 安装、升级或资料切换中断 | 恢复旧完整组件集和旧资料引用，必要时用已核验旧 Setup 修复；旧原件不自动删除 |
| 两版均不可用 | 明确停止显示并报告原因，保留资料与恢复记录；不能用残留路线或安装器成功码冒充可用 |

回退须核对真实启动、当前正确显示、写入排空及完整退出，覆盖重复操作和恢复中再次中断。窗口消失不等于所属进程全部结束；强制清理失败进程只能记为失败处理。全量替代版通过后，仍须另行决定合并与发布，本草案不授权这些动作。
