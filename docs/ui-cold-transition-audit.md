# 冷图库与 DPI 停顿：2026-10-29 审计

基线为 `3e201c2b9c4de2f87714c9019bbf85726131d4cd`（已发布候选
`7AFC2237`）。本轮没有交付新的运行时修复，也没有重打包。下面记录失败的
优化尝试，避免后续把减少调用次数当成已经解决卡顿。

## 测量范围

使用完整 `DailyAssistant` / `DesktopMainUI` 组件树、同一包内资源和隔离配置，
按固定页面、图库、窗口尺寸及 DPI 序列运行。后继分析运行在宿主 Python 中，
记录实际源码路径/哈希、调用次数、嵌套耗时、心跳、布局及图片数量；它不是重新
验证发布 EXE，也不是玩家游戏测试。DPI 由诊断上下文提供，并非操作系统切屏。

窗口不可交互、不激活、不调用游戏输入。测量包括冷进程与同进程回访，未控制
操作系统文件缓存；插桩与文件访问保护自身也有开销。数字是有限次数的墙钟观测，
没有将它们作为 CPU 占用、屏幕 FPS、p95 或长期稳定性结论。

## 首次图库

一次不带 cProfile 的完整回放复现了 **1135.66 ms** 心跳间隔。
`MapResourceBrowser._layout_cards` 的 971.46 ms 中，`update_idletasks` 占
970.58 ms，直接 Python 回调合计仅 31.62 ms。剩余时间在 Tcl/Tk 调用、原生处理
及插桩开销内，尚不能进一步归因为某个 GDI 绘制函数。

该图库为共享结构来源：26 张卡片、2 张有资源绑定；有绑定的卡片在首屏之外，
本次没有图片解码请求。因此这证明布局/占位链的停顿，不能代表缩略图解码压力。

额外对照保留全部卡片及最终几何，只在诊断中暂去掉 22 张离屏卡的圆角背景。
布局 idle 从 581.57 ms 变为 491.22 ms，仍保留约 84.5% 的耗时；差值落在此前
冷运行约 190–971 ms 的波动范围内。不能据此认定背景是主因，未采用虚拟化或
关闭圆角的产品改动。

## DPI 变更

现有同 DPI 短路有效，重复刷新约 0.09 ms，不进入组件度量或样式重建。
真正变更的主要观测成本在同步 idle：首次 120 DPI 的 action 为 4450 ms，
idle 内扣除已插桩 Python 回调后约 3091 ms；PIL resize 约 184 ms。

第二次 `apply_widgets` 是资源概览重建后对子树新控件应用 DPI，并非整树重复。
删除它会漏缩放新控件。约 540 次字体构造也不是主要耗时，不能仅凭次数归因。

尝试过两个最小改动：按实际值跳过未变的原生/几何配置；将同次圆角样式合并到
最终比例提交。17 项定向检查通过，但完整组件回放没有稳定改善：

| 操作 | 基线 action / ms | 尝试后 action / ms |
| --- | ---: | ---: |
| 首次 120 DPI | 4450 | 2355 |
| 首次 144 DPI | 1864 | 3115 |
| 返回 96 DPI | 937 | 2307 |
| 暖回访 120 DPI | 756 | 2167 |

配置调用和中间样式确有减少，但候选仍连续阻塞约 2–3 秒，增设实际值查询也增加
了部分 Python 墙钟成本。独立审查另发现，无 `on_scale` 的对话框也被施加圆角
比例，改变了本轮应保持的视觉行为。因此**撤回整个运行时尝试**，只保留诊断
记录；上述测试通过不构成性能验收。

## 后续判断边界

尚需定位同步 idle 内部的几何/绘制成本及其波动。若试验分批创建或应用布局，
必须证明每个事件循环批次的阻塞下降，且最终布局、键盘可达性、最新 size/DPI、
取消及销毁保持正确；不能把相同耗时搬到启动或后续 settle 阶段。所有 Tk 操作
仍须在 UI 线程，不能简单删除所有 idle 同步或用暖缓存结果代替首次成本。

现有检查起点：`tests/test_desktop_rounded_cache.py`、
`tests/test_display_context_snapshot.py`、`tests/test_desktop_scroll_allocation.py`
与 `app/ui_packaged_audit.py` 的完整入口。下一次产品变更应重新绑定实际源码，
记录动作及后续 idle/心跳，而非仅增加微基准或调用次数断言。
