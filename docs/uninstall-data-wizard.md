# 正式版卸载向导与资料边界

本变更以 `1f3983bd0ac999671f31adc2f8df58cfe262a4d0` 为开发基线；已发布的
1.1.1 原包源码是 `161e14f7d50b4c7ec27e2d29b67ecc060912da9c`，不得将本变更
或其测试结果写成已发布原包的行为。不触碰用户当前安装目录。

## 用户选择

正式卸载先展示资料向导，再展示选择摘要。摘要中的“否”返回修改，“取消”、
关闭按钮及 Esc 退出。默认只卸载程序，保留资料，不额外备份。

| 清除资料 | 额外备份 | 结果 |
| --- | --- | --- |
| 不勾选（默认） | 不勾选（默认） | 原资料留在安装目录，不创建长期备份副本 |
| 不勾选 | 勾选 | 原资料保留，另存一份到用户选择的外部目录 |
| 勾选 | 不勾选 | 看过原生结果后再次明确确认才清除资料，不能通过回收站恢复 |
| 勾选 | 勾选 | 先核对外部备份，卸载程序，看过原生结果后再次明确确认才清除资料 |

两项独立。未勾选备份绝不是清除许可。静默卸载只采用安全默认：保留资料、
不复制备份，没有命令行参数可悄悄开启清除。

范围是当前安装目录内：`work/`（设置、回执、日志、截图、下载缓存及历史备份）、
`assets/custom-maps/`、`_internal/assets/`、`_internal/references/`，以及
`_internal/` 中旧卸载合同保护的 JSON/JSONL、PNG/JPEG/WebP/BMP、NPZ/NPY/IDVM。
资源锁 `work/map-packages/import.lock` 始终排除。外部原始 ZIP、其他目录、未识别的
邻近文件和快照后出现的新文件不递归清除；可能留下空目录或锁文件。

## 备份与原文件保留不是同一个动作

历史 Inno 卸载日志仍拥有某些已被用户修改或导入覆盖的资源。因此，仅将原有
备份调用改为可选，会让“不备份但保留资料”的用户遭遇原生卸载删除。

现在先固定相对路径和 SHA256 清单，写入安装目录的
`.xingtu-uninstall-retained/paths.txt`、`sha256.txt`，再将每个原文件以同卷
`RenameFile` 临时移至 `files/<从零开始的清单行号>`。这不是复制或额外备份，不
额外占用一套文件正文。原生卸载完成后，保留选择将这些同一文件对象放回原位；
清除选择才对逐一复核的暂存对象执行删除。完成后清除本次空暂存目录和清单。

额外备份才使用复制。用户选择已存在的父目录，必须是安装目录外、无链接的本地
固定/可移动磁盘目录。通过目录句柄的规范化卷 GUID 路径识别 8.3/SUBST 别名，拒绝
映射网络盘和无法核实的目标，开始复制前再次核对父目录身份。每次创建独立
时间戳子目录，保留相对路径及 SHA256 清单，不覆盖已有备份。只有每个目标复制并
核对成功后才将 `INCOMPLETE.txt` 改名为 `COMPLETED.txt`。备份保存在安装目录外，
不会被本次清除操作再次删除。备份包含个人资料，不自动上传。

## 取消、失败与中断

- 向导或原生卸载确认取消：尚未备份、移动或删除资料。
- 程序/资源任务占用、链接目录、访问失败、扫描超过 32 层或 50,000 项：停止在
  原生删除之前。枚举错误不能当作空目录；使用现有资源锁，不结束用户程序。
- 用户选了备份但失败：说明原因及不完整副本路径，提供重试、不备份继续、取消。
  若此前还选择了清除，跳过失败备份时再次明确确认不可恢复后果；默认取消。
  跳过备份不会改变保留/清除的原选择。
- 临时移位失败：不开始原生卸载，退出路径尝试将已经移动的文件归位。此处不能
  “忽略继续”，因为无法保证用户选择的保留语义；这不是强制额外备份。
- 归位时原路径后来出现文件、目录或链接：不覆盖它，保留暂存原文件并报具体目录。
- 清除前先复核整个暂存集合，变化时不开始清除，尝试保留。清除过程中再次逐件
  复核，失败项及清单保留，明确告知“未全部清除”和已删除部分不可自动撤回。
- Inno 的 `usPostUninstall` 和 `usDone` 在原生删除不完整时仍可能触发，不能视为
  成功证据。清除选择将原文件暂存到 `usDone`，在原生结果/重启对话框之后明确提示
  程序可能未完全移除，再由用户决定清除还是保留；默认保留。退出路径仍恢复未清除
  的暂存资料。没有此最后确认，不进行不可恢复删除。
- 进程强杀/断电：不承诺自动恢复或整个文件系统的断电原子性。暂存清单先于移动
  持久化；再次卸载或安装发现该目录时会阻止覆盖，提示核对。恢复时退出软件，
  按 `paths.txt` 的行号对应 `files/0` 等文件，并用 `sha256.txt` 核对；只放回缺失
  路径，存在不同内容时保留两份人工核对。没有经过验证的恢复，不删除暂存目录。

路径和哈希复查防止合作进程及常见外部修改造成误覆盖；不声称能对抗任意恶意
文件系统写者在每个检查与系统调用之间的竞态。

## 验证与交付门槛

参考 Inno 官方 [卸载事件](https://jrsoftware.org/ishelp/topic_scriptevents.htm)、
[Abort 适用事件](https://jrsoftware.org/ishelp/topic_isxfunc_abort.htm)、
[RenameFile](https://jrsoftware.org/ishelp/topic_isxfunc_renamefile.htm) 和
[自定义窗体](https://jrsoftware.org/ishelp/topic_isxfunc_createcustomform.htm)。
遵循 `usUninstall` 前置准备、`usPostUninstall` 保留、`usDone` 最后清除确认、
`DeinitializeUninstall` 异常归位；兼容 Inno 6.6 前后的窗体构造签名。

云端测试 `tests/test_uninstall_data_wizard.py`：实际 Pascal 路径谓词的受限解释、
安全默认、备份失败选择、事件阶段、完整清单先行、拒绝链接/访问失败及重复中断
保护。合成文件测试验证真实文件的同卷 rename 身份保持、旧卸载所有权、部分准备
取消、归位冲突和外部备份保留；没有执行 Pascal 或 Windows 原生卸载。

Windows 必须在独立目录以同一最终源码完成：

1. 正式与私测脚本编译，确认 include 与构建回执的 recipe hash 一致；不运行或覆盖现用正式目录。
2. 新装和旧 1.1.1 升级后的卸载，覆盖四种选择组合、默认及静默卸载。
3. 向导返回修改、取消、Esc/关闭、原生确认取消；普通/高 DPI 实际像素和键盘操作。
4. 低磁盘/不可写备份位置的重试、跳过及取消；跳过后保留选择不变。
5. 资源任务占用、只读/无法移动文件、路径链接、归位冲突和删除失败。
6. 中断后暂存清单存在且下一次安装/卸载拒绝覆盖；人工按清单恢复的原字节核对。
7. 用户图包、修改过的作者图片、自定义路线、未知邻居、外部 ZIP 和新出现的文件边界。

编译、独立安装/卸载、真实 GUI 和已发布产物是不同阶段。Windows 证据未完成前，
不得把源码合同和合成文件测试称为卸载向导验收通过。
