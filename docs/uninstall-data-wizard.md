# 安装与更新：主动卸载与升级入口

本轮采用已明确决定的“复用 Inno，主动卸载默认全清”。旧向导的默认保留、备份选项和卸载末尾再选清除不再适用；历史版本行为仍以对应 Git 提交为准。相邻模块是地图资源、自定义图库；不改它们单独删除图包、导入或显示的规则，不改识别逻辑。

## 为什么旧版会残留

旧 Inno 的精确程序投影和 `_installer-owned-files.txt` 都排除 `work/`，运行时创建的设置、下载、图包回执、日志和升级备份不会因此被原生卸载删除。旧向导默认不扫描这些资料；即使选择清除，也只扫描安装目录中的部分资源类别，还会排除资源锁。正式 Qt 客户端另经 `RuntimePaths.imported_resource_root` 使用 `%LOCALAPPDATA%/Xingtu/resources`，这个外置导入根没有进入旧向导。游戏启动联动的本地账本和退出提示登记也按旧约定保留。

这些是源码可确认的机制，不是对某台用户机器实际残留的现场验收。没有读取、清理用户当前安装或真实资料。

## 清理流程与边界

主动卸载只有继续或取消，没有保留资料选项。静默调用沿用同一全清实现。确认发生在任何资料删除前；更新版本应运行安装包，不能先运行全清卸载。

1. Inno 保留既有未完成升级的阻止规则，在获取当前安装独占资源锁后再次核对；未提交事务须先恢复，不能清掉其证据。生产实例按原共享生命周期停用并等待游戏启动监听器；不强制结束进程。
2. 根据构建时已有的助手库存保护模式，核对已安装卸载助手的精确库存，把核对过的助手和普通权限运行库复制到临时目录。运行临时副本，不执行安装目录中可能被修改的 Python 或旧维护工具。
3. 卸载助手验证构建内身份、原生安装登记、当前用户、父卸载器进程和同一借用锁；完整检查产品归属、其他实例、文件占用、链接及所有待清理对象后才开始删除。修改过的配置和自建内容仍在产品数据范围，不以旧内容哈希不符为由保留。
4. 助手清除确认归属的资料；卸载助手及其运行库、库存、安装身份和归属清单留给原生 Inno，保证资料清理中途失败仍可处理剩余项后重试。成功回读 `status=cleared` 才允许 Inno 开始原生程序卸载。失败停止原生卸载，不把已删除部分说成已恢复。
5. 助手精确进程已退出且回执确认成功后，先清除已核实的旧快捷方式，对同一个资源锁句柄设置删除并关闭，只移除空的资料祖先目录；这些操作任一失败，仍在原生卸载前停止，保留助手、原生文件和登记供重试。安装和卸载均原子持有同渠道的进程期维护互斥，避免关闭资料锁后另一份新安装程序进入。当前版本以前的安装程序不认识这个新增互斥，不能据此承诺旧安装程序并发执行安全。
6. Inno 原生处理本安装的卸载登记、所记录的当前快捷方式及卸载器。尾声只核对空安装根及当前入口；发现剩余项必须保留并明确未完成，说明卸载入口可能已删除，需要联系维护者核对残留。当前安装包会拒绝未登记的非空目录，不能把重新运行安装包写成已证明可用的修复入口，也不声称原生文件已删除后仍可直接重试。原生 Inno 的退出码和 `usDone` 不能单独证明整机清空；仍需完整安装验收核对自删除、登记和入口。

| 范围 | 处理 |
| --- | --- |
| 当前已登记安装目录 | 程序、确认归属的运行目录、资源、设置、缓存、下载、自建路线图库、迁移暂存和历史备份均全清 |
| 当前生产实例的外置导入根 | 核实当前用户和实例无共享冲突后，持有该根自己的资源锁清理；不是只持安装目录锁 |
| 当前安装的游戏启动联动 | 停用准确的登录启动项，清理本安装的本地账本与退出提示登记；不碰其他实例或用户 |
| 旧 QtIFW 维护残留 | 本安装根中可确认归属的维护文件纳入主动卸载；不运行旧卸载器 |
| 外部原始包、其他软件和实例 | 不删除。根邻居归属不明、共享、链接、硬链接、权限或占用问题必须明确失败和剩余项 |
| 漫游资料目录、全机共享资料目录 | 当前源码没有可直接认领的相应产品数据根；不能按目录名全盘搜索或笼统删除，旧版若有资料须由迁移盘点补充证据 |

失败结果包含 `result.ini`、`error.txt`、`remaining.txt`。`mutationStarted` 区分尚未开始删除与部分删除/不确定；只有完整可信回执证明未发生变更，Inno 才尝试恢复先前开启的游戏启动联动。部分删除或助手崩溃不重新启用可能已损坏的程序。路径可安全访问时，Inno 另存本安装根的 `.xingtu-uninstall-failed.txt` 供重试核对；下一次主动全清将其纳入。

## 简单页面与有限等待

可见流程沿用 Inno 原生的一个全清确认、一个进度窗口和完成提示，没有保留资料选项。
确认文案直接覆盖原生 `ConfirmUninstall`，不在初始化时再加确认。静默模式不额外弹重试框。
占用按本安装准确路径检查，不按程序名字关进程。助手预检对准确主程序持有写入检查句柄：
单独的删除权限在 Windows 上未必能及早发现运行中的程序；写入句柄还能阻止预检后的重新启动。

资料助手默认有 120 秒业务期限，在扫描、复核和每项删除前检查；原生父卸载器另给 135 秒硬等待，
游戏启动监听的每条卸载控制命令给 15 秒。进度窗口显示当前阶段和已等待秒数，不把时间当成完成百分比。
父进程直接持有创建时返回的子进程句柄，超时只终止本次控制/助手进程，最多再核实退出 5 秒；
异常退出路径还会进行一次最多 5 秒的安全收尾。没有按名字批量关闭，也不会关闭游戏。
如仍不能核实退出，明确禁止重试/启动，要求重启后重新卸载；不能把可能仍在删除的助手报成完成。

正常失败显示中文原因和下一步，原生删除前可点“重试”或取消；每次尝试使用新的临时回执目录，
不接受上次成功结果。重试不能抹掉前次已经部分删除的事实。权限、占用、文件缺失、崩溃或期限失败
均不改权限、不吞错；已缺失的普通程序文件不阻止核实剩余资料，身份/必要助手缺失则要求对应安装包修复。
若上次恰好在删除外置资源锁后停止，只允许已核实当前用户、唯一实例和真实句柄的纯空尾目录继续清除；
只要缺锁根仍有任意文件或未知目录就继续停止，不能借重试放宽资料互斥。

## 升级与第 2 项迁移接口

本项保留 PR #142 的程序升级 preserve 会话及现有持久化协调器，不恢复默认资源种包，不把全清助手接到升级链。新装只接受空目录；重装/覆盖升级必须绑定本安装渠道原生登记的原目录。正式版和各测试渠道互相拒绝同根、父子重叠。

原 Inno 在成功升级后也留下每次程序文件的暂存副本。本项仅在整体升级已核实提交后删除本次创建的精确副本和元数据；不递归清理历史备份或协调器恢复记录。清理失败明确提示路径并返回非零安装结果，未提交或失败的恢复证据保留。

`qt-installer-target.iss` 在获取资源锁、停用监听或复制程序前识别旧维护工具/元数据；发现旧 QtIFW 时明确停止。当前还没有接通第 2 项迁移实现，不能宣称 QtIFW 接管或跨目录迁移完成，也不接受靠可编辑“已完成”文件跳过迁移。不得先写新程序，再直接运行旧 QtIFW 卸载器。

第 2 项仍负责迁移核心、协议和旧维护工具退出顺序。本项的整合接缝为：在 `InstallerTargetError` 的旧版停止分支之前接入它的持久化准备/复制/验证/提交/失败恢复入口；只有其正式结果能证明旧实例资料已迁移、完整资源和自建内容可用、旧维护工具已退出且不会撤销新文件，才继续既有 Inno preserve 协调器。成功后清理临时备份和旧入口；未提交/失败状态保留恢复证据。这里没有空迁移实现。

## 检查与交付范围

改动须从 `PYTHONPATH=app;tools;tests;experiments/qt_quick`、`PYTHONUTF8=1` 执行定向回归。真实清理核心用可丢弃目录和原生 Windows 文件句柄验证，注册表/身份替身的范围在测试中注明。Inno 接缝测试及实际编译只证明对应层级，不能替代安装、升级、默认全清和失败恢复的联合验收。

本分支不合并、不发布、不创建标签、不上传安装包。完整最终验收留第 4 项，正式发布仍须 huan 本机验收。
