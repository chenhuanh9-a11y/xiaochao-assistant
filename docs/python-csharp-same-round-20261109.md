# 星图：Python 与 C# 三路线同轮对照（2026-11-09）

本报告只使用本轮新数据，没有将旧轮结果拼表。**局部迁移网格计算在本轮取得最明显的热延迟收益；无 Python 的 C# 链路冷启动更快，但热端到端 p95 和工作集更高。** 这些结果不足以推导“全部换成 C# 就全面更快、更省内存”。

机器可读的完整汇总、各进程轮次和冷请求原值见 [摘要证据](evidence/python-csharp-same-round-20261109.json)。这是报告提交，不包含软件变更、安装包、实验源码或私有录制素材。

## 范围与同条件方法

原 Python 源码快照为 [e78d4ee](https://github.com/chenhuanh9-a11y/xiaochao-assistant/commit/e78d4eebbd374e7cee260ff644fbdb7f4f5e1ee2)。独立实验实现仅覆盖已验证的 **S0／噩梦／2F 初次识别路径**，并非当前主分支的全产品性能或完整产品已迁移。

三路线均使用同一台 Windows 11 x64 机器、同一 WPF 外壳二进制、同一张本地保留的真实录制帧（2560×1417，逐像素1:1显示）、同一855文件/223823255字节资源快照、26个目标楼层竞争者、相同配置、二进制管道、截图和屏幕回读。楼层2是配置输入，地图ID与历史姿态未作为答案输入。

| 路线 | 实际计算 |
| --- | --- |
| Python 原链 | WPF + 原 Python worker |
| 局部 C# | WPF + Python worker，仅 `_grid` 由持久 C# 子进程计算 |
| 无 Python C# 链 | WPF + 独立 C# 计算进程；身份、最终pose、验证与结构渲染均不调用Python |

固定构建后按六种顺序交错：`ABC / BCA / CAB / ACB / CBA / BAC`，A/B/C分别为上述三路线。每条路线在首、中、末位置各出现两次，每个新进程18次请求。每路线 **6次新进程首次请求 + 102次热请求 = 108次**，正式采样合计324次。所有尾部波动均保留。

位置固定为第二屏 `(2560,0)`、96 DPI。外部输入窗口不计入任何路线的进程树内存。正式采样期间没有构建、Git上传或其他本实验负载；Build Tools安装及旧实验进程事先已结束。其他桌面应用和系统服务保持运行，累计CPU计数确认存在背景活动；这不是完全空闲的实验室环境，也不能将某次抖动归因于某个后台进程。

本帧实际分支为快速候选搜索后 `fast-ambiguous`，再由当前帧entry重新验证并经canonical residual确认。局部C#的候选确实进入后续计算；无Python路线的最终pose确实由C#生成。预处理或静态参考缓存不等于缓存身份/最终pose，每次仍执行当前帧求解和验证。

## 先验证等价，再汇总

正式采样前，三路线各执行真实帧→黑帧→恢复→黑帧，12次功能调用均按预期通过，旧结构确实清除，随后恢复。

本轮保存的36份完整结果，原有非计时字段严格一致，保存的RGBA逐像素一致，36幅实际屏幕在状态条以下的完整二值结构区域差异均为0。仅排除计时字段以及后端专有的标签、进程ID/网格计时元数据，不对矩阵、候选、残差或接受判定设置容差或取整。

正式三路线各108次成功、0次失败、0次缺失回读；结构、状态、透明、点击命中检查和进程内存查询均无缺失。首帧屏幕截图与共同显示输入逐像素一致。只保存了每进程首末的完整结果/屏幕，其余轮次保存原始计时和状态，不能说324份完整fit对象均已比较。

这是同一张帧的重复时延测量，不是324张独立地图的识别准确率，也不证明自动楼层识别或真实游戏验收。

## 热请求

单位ms；p50/p95使用nearest rank，每路线102个热样本。端到端起点为GDI截图开始，终点为状态、实际结构和透明像素经过DwmFlush/GetPixel回读成功；不包括截图前固定等待，不是物理刷新或游戏按键到显示延迟。`fit`是实际贴合调用，包含候选、回退和最终验证，嵌套在worker及端到端内。

| 路线 | fit p50 / p95 / max | 端到端 p50 / p95 / max |
| --- | ---: | ---: |
| Python 原链 | 182.5 / 193.1 / 194.1 | 350.3 / 361.7 / 366.0 |
| 局部 C# 网格 | 111.5 / 113.8 / 120.5 | 278.1 / 285.0 / 288.4 |
| 无 Python C# 链 | 169.1 / 256.8 / 265.9 | 336.8 / 433.9 / 449.8 |

以下差值和百分比均以**本轮Python原链**为基线，负值表示耗时下降：

| 路线 | fit p50变化 | fit p95变化 | 端到端 p50变化 | 端到端 p95变化 |
| --- | ---: | ---: | ---: | ---: |
| 局部 C# 网格 | -71.0ms / -38.9% | -79.4ms / -41.1% | -72.2ms / -20.6% | -76.7ms / -21.2% |
| 无 Python C# 链 | -13.4ms / -7.4% | +63.7ms / +33.0% | -13.5ms / -3.9% | +72.2ms / +20.0% |

无Python路线的尾部不是单独一轮被隐藏的异常：六个进程各自17个热请求的端到端p95依次为433.9、445.4、436.6、449.8、438.9、444.5ms。这些小样本分位数是描述值，不是稳定服务尾延迟的承诺。

## 差异出现在哪一段

下表为各段热p50，单位ms。各段中位数不能当成同一次请求相加，嵌套时间也不能重复累计。

| 阶段 | Python | 局部C# | 无Python C# |
| --- | ---: | ---: | ---: |
| 共用截图/BMP封装 | 26.7 | 26.7 | 26.7 |
| 解码 | 7.1 | 7.1 | 4.8 |
| rank | 43.2 | 43.2 | 42.1 |
| fit | 182.5 | 111.5 | 169.1 |
| 结构渲染/PNG编码 | 35.2 | 35.3 | 44.6 |
| worker总计 | 269.1 | 197.2 | 261.1 |
| 管道往返（含worker） | 279.3 | 207.7 | 267.7 |
| 每样本往返减worker | 10.2 | 10.2 | 6.2 |
| WPF解码/赋值 | 13.0 | 12.6 | 13.0 |
| 赋值后屏幕回读 | 29.8 | 30.5 | 30.1 |

观察上，无Python完整链比局部C#网格的fit p50多57.5ms、fit p95多143.0ms；渲染p50多9.4ms，而端到端p50多58.7ms。外壳、截图、赋值与屏幕回读相近，差异主要出现在计算进程的fit和渲染。现有分段计时不能继续把fit内部差异归因于某一个算子、分配策略或语言本身。

没有采集分配/GC事件、GPU显存或系统调度追踪，**不能声称尾部原因就是GC**。这些只是下一轮可检验的原因假设。

## 新进程首次结果

每路线只有6个新进程，以下报告中位数及最小—最大值，不将其p95包装为稳定尾延迟。操作系统文件缓存没有清空，因此是进程冷启动，不是Windows冷启动。

| 路线 | 启动到首结果：中位数［范围］ms | 首次截图到结果：中位数［范围］ms |
| --- | ---: | ---: |
| Python 原链 | 3329.5［3294.5—3336.9］ | 2241.3［2213.8—2264.3］ |
| 局部 C# 网格 | 3365.4［3338.2—3385.3］ | 2197.9［2172.5—2215.7］ |
| 无 Python C# 链 | 1467.2［1452.4—1519.3］ | 827.0［801.5—879.2］ |

相对本轮Python原链，局部C#启动到首结果多35.9ms（+1.1%），无Python路线少1862.3ms（-55.9%）。这些是当前实现的成绩：原Python工厂建立完整多楼层/适配对象，C#实验只初始化声明的2F链；原Python的OpenCV导入发生在ready前，C#部分原生加载发生在首次解码。没有另改基线做等初始化范围的辅助实验，不能把全部冷启动差异归因于语言。

## 完整进程树内存

每次结果回读后采集全部后代，包括WPF、算法、C#网格子进程和conhost。MiB=1048576字节。WorkingSet可能重复计入共享页，是采样值而非瞬时峰值；PrivateBytes是提交量，不能当实际RAM。

| 路线 | WorkingSet p50 / p95 / max MiB | PrivateBytes p50 / p95 / max MiB | 进程数 |
| --- | ---: | ---: | ---: |
| Python 原链 | 437.4 / 446.8 / 449.2 | 1065.7 / 1077.6 / 1089.9 | 3 |
| 局部 C# 网格 | 510.0 / 529.6 / 533.3 | 1111.9 / 1127.9 / 1132.7 | 5 |
| 无 Python C# 链 | 645.5 / 783.5 / 788.4 | 686.4 / 825.0 / 829.1 | 3 |

相对本轮Python原链，工作集中位数分别增加72.6MiB（16.6%）和208.1MiB（47.6%）。C#完整链提交量较低、工作集较高，两项事实同时保留。无Python路线的108份进程树均没有Python进程。摘要还包含各进程角色的工作集/提交量和ready后的空闲采样；各角色中位数不能直接相加来替代联合中位数，ready时初始化阶段也并不完全相同。
